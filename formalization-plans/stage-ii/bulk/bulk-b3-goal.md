## 4. ビルドの管理

- 一括レーンは**共有の鍵（`with_build_lock.sh`）を使わず**、自分で管理する（ユーザー決定）。他のレーンは共有の鍵を使い続ける。
- 機械は 64 GB。一括レーンの重い処理は**同時に 32 GB・4 ジョブまで**（verify は 4 ジョブ・32 GB）。大きい監査を同時に二本流さない。
- **昼（JST 8〜23 時）は軽い処理だけ**（2 ジョブまで、verify と全体監査は流さない）。昼は実装のレーンが CPU を使うため。重い処理は夜（23〜8 時）に。
- Lake の成果物キャッシュは共有のまま（`~/.zshenv` の設定を使う）。

## 5. 止まらずに進める規則

- 失敗したら、原因を調べて直し、同じ検査を最初からやり直す。直すのに数学の中身の変更や範囲の拡大が要るなら、**そのモジュールの移動だけを取り下げて元の場所に残し**（依存の閉包ごと）、記録して先へ進む。取り下げたものは B3′ の候補として一覧にする。
- 保存比較の説明のつかない差分は 0 にする。0 にできないものは、上と同じく移動を取り下げて 0 にする。
- 判断に迷うものは、承認済みの範囲の狭い方を選び、報告に書く。調整役の返事を待たない。
- 止まるのは、(a) 二晩目の終わり、(b) 基準の main が予期せず動いた（調整役が取り込まないので起きないはず）、(c) 他のレーンの作業木・枝や main の作業木に書き込まないと進めない、の三つだけ。(b)(c) は記録して、できる所までで終える。
