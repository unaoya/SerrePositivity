作成：2026-11-19（調整役）。決定：ユーザー（11-19 夜）。目標と規則は `declaration-inventory-w1.md` §0。二つのレビュー（`review-cleanup-plan.md` と監視のチャットのレビュー）を受けた直し。

## 0. 背景と決定

行の内訳（11-19、字面、Archive を除く 34,336 本・309 万行）：コード 53.4%、空行 11.3%、namespace・open・variable など 9.8%、モジュールの docstring 8.8%、宣言の docstring 8.4%、import 5.4%、`set_option` 1.7%、別名 1.0%。宣言が 3 個以下のファイルは 17,545 本・111 万行（コードは 54 万行）。`_root_.SerrePositivity.…` の完全修飾が全文字の 28.7%、100 桁を超える行が 16.8%。100 行以上の宣言は 99 件・1.3 万行（0.4%）。主定理（`Paper/Statement`）から import でたどれるのは約 11%。

ユーザーの決定（11-19 夜）：
1. **範囲**：主定理につながっていない文献の形式化（Kerodon・KST など）は残す。
2. **完全修飾の短縮は慎重に**：全体には一括でかけない。見本（B）の中でだけ試し、名前の隠れ方・宇宙の捕まり方（11-02 の教訓）を型の比較で確かめて、結果を報告する。
3. **docstring**：補助の宣言は一行でよい（四項目は、文献の項目に当たる宣言と主要な定義に）。
4. **一行は 100 文字まで**。
5. **見本は二つ**：`LengthAlgebra/` と `Spectra/General/`。
6. 行数の報告は三つを並べる：空行とコメントを除いたコードの行、文字数、100 桁を超える行の数。ファイル数と宣言数も。

## A. 意味を変えない削減（⑦、DI-W1 の前に）

レーン ⑦（`../SerrePositivity-ic`、`refactor/infinity-consolidation`）。IC-2 の第 2 組を片付けてから、DI-W1 の前に行う（目録を採った後に別名を消すとキーが変わるため）。**見本の二つのディレクトリ（`LengthAlgebra/`・`Spectra/General/`）には触らない**（⑧ が持つ）。

1. **別名を消す**：`deprecated_alias`（約 13,200）・`deprecated_alias_util`（約 2,000）・`alias`（45）。
   - 先に段 0（紙）：別名ごとの行き先、旧名を使う所（本体・scripts・blueprint・`research/` の対応表・`scripts/refactor/targets/*.json`・`research/k-coverage/maps/legacy-kernel-evidence.json`・drafts）の数。対応表が旧名で名指ししている行は、新名に書き換える（固定する宣言の名指しを失わない）。
   - 適用：使う所を新名に書き換えてから別名を消す。別名だけになったファイルは消し、import を追従する。数学の `alias`（改名の跡でないもの）は残す。
   - 判定：root のビルド、消す前後で別名でない宣言の（カーネル名・型）が一致、対応表の名指しの解決数が減らない。
2. **`set_option` を寄せる**：`backward.isDefEq.respectTransparency false`（約 28,900 本）・`…respectTransparency.types false`（約 21,000 本）・`backward.defeqAttrib.useBackward true`（約 1,100 本）。
   - 先に試す：`lakefile.toml` の `[leanOptions]` に移すと、今その行を持たないファイル（数千本）の挙動が変わる。持たないファイルが寄せた後も通るかを、塊で試してから決める。通らないファイルが多ければ、その option は寄せずに報告する（逆向きの `set_option … true` をファイルに足す案は、数が少ないときだけ）。blueprint と scripts の Lean への影響も確かめる。
   - これは全体の再ビルドになる。別名と同じ束にして、再ビルドを一度にする。
3. 段 0 の報告で一度止まる（数と、試した結果）。適用は調整役の連絡の後。適用の後、調整役が root・全監査・sorry の閉包で取り込む。そのあと DI-W1 へ。

## B. 最後まで通した見本（⑧）

レーン ⑧（`../SerrePositivity-cited`、`research/cited-coverage`）。この見本に限り、**二つのディレクトリの中で Lean を変えてよい**。ビルドは `--class bulk` の鍵で、対象ビルドだけ（root 全体は調整役）。

- 対象：`SerrePositivity/LengthAlgebra/`（17 本）と `SerrePositivity/Spectra/General/`（46 本）、合わせて約 11,000 行。外からの利用は `LengthAlgebra` が Asymptotic・CLMST・Paper・AlgebraicGeometry・KST など、`Spectra/General` は Spectra の中と Models。
- やること（一つのディレクトリずつ、整理を最後まで）：
  1. 宣言を全部読み、概念の辞書（主要な概念と補助の定義）と、宣言 → 概念の対応を作る（CD-W1 の見本を兼ねる。CD-W1 §4 の列で）。
  2. 重複をまとめ、補題を整理し、証明を短くする。固定版の Mathlib にあるものは Mathlib に置き換える（関係は「そのまま・特殊化・同型による別の表示」で記録）。Mathlib に送る価値のあるものは記録だけ。
  3. ファイルをまとめ直す（一つのファイルは一つのまとまり、冒頭の docstring で中身が分かる）。ディレクトリの中の構成は Mathlib を参考に。
  4. 一行 100 文字まで。docstring は §0 の 3 の規則で。完全修飾の短縮はここで試す（§0 の 2）。
- 変えないもの：対応表が名指しする宣言の名前と主張（「一部」も含む）。ディレクトリの外から使われている宣言の名前と型は、原則そのまま。変えたいときは、古い名前を新しいものから一行で出して残し、一覧にする（外のファイルは import の行のほかは触らない。⑦ の A と重ならないように）。
- 判定：対象ビルド、固定する宣言と外から使われる宣言の型が前後で一致（カーネルの型で比べる）、公理が増えない、sorry が増えない。
- 報告（`report-cleanup-pilot.md`）：前後の、ファイルの一覧と冒頭の docstring、ファイル数・宣言数・コードの行・文字数・100 桁を超える行。何で減ったかの内訳（統合で消えた頭、消えた重複、短くなった証明、Mathlib への置き換え）。かかった時間（読む・書き換える・ビルド）。うまくいかなかったこと、機械にできなかったこと。完全修飾の短縮の結果。
- 一つ目（`LengthAlgebra`）が終わった所でコミットして短く報告し、止まらずに二つ目へ。二つ目の報告で止まる。ユーザーが前後を見て「把握しやすいか」を判定する。
