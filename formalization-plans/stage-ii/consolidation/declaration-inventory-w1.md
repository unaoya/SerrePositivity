# 指示書 DI-W1：宣言の目録（段 0）

作成：2026-11-19（調整役）。決定：ユーザー（11-19）。

## 0. 目標と、IC-2 との関係

整理の目標（ユーザー、11-19）は次の三つ。

1. 全てのファイルの内容をブループリントで捕捉する。
2. その上で、内容に合わせたディレクトリ構成とファイルの分割に基づいて配置する。
3. 文献の形式化がどこまで進んだかを確認できる。

検討の単位は**ファイルではなく宣言**とする（ユーザー）。ファイルは細かく割れすぎている（11-19 の実測、Archive を除く：34,336 本・163,207 宣言・312 万行、1 ファイルの宣言の中央値 3・行の中央値 72、宣言 3 個以下が 17,542 本）。補助のファイルを減らすのも整理の目的に入る。

ブループリントは二つにする（ユーザー承認）：
- **文献のブループリント**（今のもの、`blueprint/`）：文献の項目ごとの主張・状態・結んだ宣言。進み具合を見る。
- **把握のブループリント**（新しく作る）：本体の側から見る。節点は宣言の**まとまり**（文献の項目の補助、または本体の構成の主題）で、宣言は節点の中の表にする。

**進め方の順序**（ユーザー、11-19）：全宣言を把握する → 内容ごとに整理する → 重複などをまとめる → ファイルを決める → ディレクトリ構成を決める。ディレクトリは最後に決め、前の段の結果から導く。

**整理の規則の決定**（ユーザー、11-19 午後）：
- 順序：把握 → 概念の整理（概念のブループリントは全ての宣言を必ず覆う）→ 補題・証明の簡略化と重複の統合、Mathlib への置き換え → ファイル・ディレクトリ → 文献のブループリント（二段目：文献の形式化の度合いの確認）→ 残りの計画。
- **文献にある定義・定理・補題そのものは変えない**。その準備として作った宣言は、主張も証明も変えてよい（最終的に証明が正しく通ること）。整理のために Lean のコードを書くこと（証明の短縮、重複の統合、一般の補題への置き換え）は「新しい形式化」に当たらず、許される。
- Mathlib にあるものは Mathlib に置き換え、Mathlib に準拠した形にする。Mathlib に送る価値のあるものは記録する（送るかどうかは別）。
- 目指す状態：人が読めるように整理され、ファイル数・行数が少なく、分野の専門家が把握しやすい。行数を減らすことがベンチマークの一つ。「把握しやすいか」の判定はユーザー。ディレクトリの木は Mathlib の構造を参考にし、ファイルは一つのまとまりで docstring から中身が分かり、概念のブループリントの目次とディレクトリが対応する。
- この段 0（DI-W1）自体は紙と書き出しだけで、Lean のソースは変えない（下の §1 のまま）。上の規則は適用の段のもの。

**IC-2 は止める**（ユーザー承認）。今の組をコミットして止まる。残りの組への一括の承認は取り下げる。IC-2〜5 と BS の整理は、この目録の上で「まとめ直し＋移動」の束に組み直す（同じ宣言を二度動かさないため）。IC-2 の段 0 の資料（`research/infinity-consolidation-w2/`）は捨てずに、組み直しの入力にする。

### 前半（ここで一度止まる）

1. **宣言の表**（`decls.csv.gz`）：`SerrePositivity/` の下の**全てのファイルの全ての宣言**（Archive だけ除く。11-19 ユーザー）。
   - 抜き出しは Lean のメタプログラミングで行う（環境の定数と宣言の位置 `declRangeExt` から。正規表現で数えたものは照合にだけ使う）。root から届かないモジュールも含めるため、Archive 以外の全モジュールを import する書き出し用の入口を塊に分けて作り、塊ごとに書き出して合わせる。
   - 列は、名前、モジュール、ファイル:行の範囲、種類、private か、自動生成か、自動生成なら親の宣言、docstring の有無、文献の属性（`@[cite]`・`@[kerodon]`）。
   - **自動生成の宣言**（`_proof_`・`match_`・等式の補題・構造体の射影や `mk`・`instance` の自動名など）は除かずに一覧に入れ、自動生成と分かる印と親の宣言を付ける。整理の対象にはしない（数えるときは分けて数える）。
1″. **行の内訳と長い宣言**（ベンチマークの基準値）：ファイルごと・ディレクトリごとに、主張の行、証明（本体）の行、docstring の行、コメントと空行、import などその他の行。宣言ごとの証明の行数の分布と、長いものの上位の一覧。全体の合計（ファイル数、行数、宣言数、1 ファイルの宣言の中央値）を基準値として報告の頭に置く。
1′. **抜き出しの二重の確認**（ファイルごと）：`files.csv` に、Archive 以外の全ての `.lean` ファイルを一行ずつ。
   - (a) ファイルごとに、書き出しにそのモジュールが現れたか（宣言が 0 個のファイルも行を持つ）。
   - (b) ファイルごとに、ソースの宣言（`theorem`・`def`・`instance`・`structure` などのキーワードの出現と、`variable`・`notation`・`macro`・`elab`・`initialize`・`attribute` などの宣言でないコマンドを区別した字面の数え）と、Lean が書き出した宣言（自動生成を除き、位置がそのファイルにあるもの）を位置で突き合わせる。
   - 一致しないファイルは全件を `mismatches.csv` に、理由（macro が作る宣言、`mutual`、`deriving`、section の中の名前の付き方など）と一緒に。理由の付かないものが 0 になるまで抜き出しを直す。
2. **依存の辺**（`edges.csv.gz`）：本体の宣言から本体の宣言への辺（型と本体の両方。自動生成の宣言を経由する辺は親に寄せた辺も出す）。
3. **根**：(i) 論文の主定理と sorry の閉包の対象、(ii) 対応表（`research/*-coverage` のすべての review と items）が名指しする宣言と、その項目・状態、(iii) 全監査の期待の一覧。根ごとに件数。
4. **役割**：宣言ごとに一つ。
   - 主張：(ii) で名指しされている。
   - 補助：主張から依存をたどって届く。どの項目の補助かを付ける（最も近い項目。複数の文献の項目から届くものは、その一覧）。
   - 本体の構成：(i) から届くが (ii) からは届かない。
   - 監査だけ：(iii) からだけ届く。
   - 使われない：どこからも届かない。
   役割ごとの宣言数と行数を、ディレクトリごとに集計する。
5. **ファイルの所見**：ファイルごとに、宣言の役割と持ち主（項目か主題）の内訳。印を付けるもの：複数の文献にまたがる（分割の候補）、宣言 3 個以下（まとめる候補）、使われない宣言だけ（Archive の候補、提案だけ）。

6. **重複の候補**：宣言の型（`decl_snapshot.lean` の正規化した型のハッシュ）が一致する組、定義の本体が一致する組を全件。加えて、名前か docstring の文献の番号が同じで型が違う組（一方が他方の特殊化か、仮定の違い）を候補として。組ごとに、宣言、ファイル、使う側の数、どちらが原典に近い一般の形か（分かる範囲で）。`research/bs-refactor-audit` と台帳（`refactor-ledger.md`）の既知の重複（BR 番号）との対応も付ける。

前半の報告で止まる。まとまりの切り方（後半の 7）は、前半の数字を見て調整役とユーザーで決める。

### 後半（調整役の連絡の後）

7. **まとまりの案**：宣言を、文献の項目の補助、または本体の構成の主題ごとにまとめる。まとまりごとに、仮の題、宣言、今のファイル、置き場所の案（文献の節か主題のディレクトリ）を書く。把握のブループリントの節点の入力として、`groups.json` も出す（生成器は調整役が書く）。
8. **重複をまとめる案**：6 の組ごとに、残す宣言（原典に近い一般の形）と、系にするか置き換える宣言、使う側の書き換えの数。主張・一般性を落とす提案はしない。新しい数学が要るもの（一般の形がまだない）は印を付けて外に出す。
9. **ファイルの案**：まとまりと 8 の後の宣言から決め直したファイルの数と行の分布（今との比較）。IC-2 の段 0 の `placement.csv` との食い違い。
10. **ディレクトリの案**：9 のファイルの置き場所（文献の節、模型、本体の構成の主題）。今のディレクトリとの対応表。
11. **組み直しの案**：「まとめ直し＋移動」の束の順序と所要時間の見込み（適用・保存比較・調整役の検証）。束は IC-2〜5 と BS の整理の範囲を覆う。

## 3. 守ること

- 文献にある定義・定理・補題（対応表が名指しする宣言）の主張を変える提案はしない。準備の宣言は、主張・証明を変える提案（一般の補題への統合、Mathlib への置き換え、証明の短縮）をしてよい（§0 の規則）。
- 削除・Archive への移動は提案だけ。決めるのはユーザー。
- 報告の形は IC-W1 と同じく「一覧：済み n／全体 m（うち追加 k）」（単位は前半の 1〜6、後半の 7〜11）。
