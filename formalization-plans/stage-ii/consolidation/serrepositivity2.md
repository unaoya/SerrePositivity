# SerrePositivity2：新しいプロジェクトの決定の記録

2026-11-21 開始。場所は隣の `SerrePositivity2`（git は手元のみ）。経緯は [enrichment-w1.md](enrichment-w1.md) の決定 10 と [cleanup-log.md](cleanup-log.md) §26。プロジェクトの規則は、その README が正。ここには、決定とその理由を足していく。

## 決定 1：Mathlib だけに乗せて、下から作る（ユーザー、11-21）

- 依存は Mathlib とそのプロジェクトのファイルだけ。旧い側を import しない。旧いコードは参照しながら書く。
- 持ってくるファイルは、必要になった時に、ファイルごとに「写す／要る分だけ新しく書く／書き直す」を決める。一番下の層は、基準に届かないものを写さない。
- 下の層は、上を積む前にユーザーが読んで固める。
- 未決：段 3e の後に何を積むか（第一候補は対称スペクトルの豊穣化）。全体を新しい側に移すか、旧い側とつなぐか。

## 決定 2：文献の印を最初から強制する（ユーザー、11-21）

- 公開の宣言は、文献の番号（`@[cite KEY "番号"]`）か、補助の印（どの宣言のための補助か）のどちらかを持つ。どちらも無いものが 1 件でもあれば、検査は失敗。自動で作られる宣言は、元の宣言の印を引き継ぐ。
- 書く前に対応表を作る：扱う節の項目を全部挙げ、「形式化する／Mathlib にある（名前）／今回は扱わない（理由）／後で」に分ける。
- 主張は原文と並べ、違い（仮定、向き、合成の順）を記録する。番号は `~/serre-evidence/references/` の本文で確かめる。本文が無い文献は、ユーザーに頼む。
- Mathlib にあるものは書き直さず、Mathlib の宣言を使う。
- 補助の印の乱用を防ぐ：補助の割合を数字で出し、読み直しで調整役が一つずつ確かめる。

## 決定 3：全宣言の文書は doc-gen4 で、このプロジェクトの分だけ（ユーザー、11-21）

- Mathlib のドキュメントと同じ形のものを作る。**Mathlib の分は生成しない。** Mathlib の宣言へのリンクは、公開されているドキュメントに向ける（できなければリンクなし）。
- その上に、文献の印から作る一覧を一枚置く：文献の章・節の順、原文、対応する宣言へのリンク、まだ書いていない項目、冒頭に数字（宣言の数、文献の印の割合、`sorry`、ユーザーが読んだ割合）。
- 読んだかどうかは、小さな台帳に調整役が記録する。
- 作るのは ⑦（LI-W1 段 1 の報告の後）。更新は段の区切りごと。

## 保留：数学の読み物をどこに書くか

docstring（Mathlib と同じ。正が一か所）、leanblueprint（標準。LaTeX を別に書くのでずれる）、Verso（ずれを検出できるが重く、旧い側で建たなくなった）。仕組みは先に決めない。段 3a′・3b のコードで doc-gen4 の出力を見て、docstring で足りない所（全体の筋など）が見えてから決める。
