# AR-W1 段2　監査のゼロからの設計のレビュー

**結論。G1 の対象一覧と新旧の並行計測は始めてよい。現案で旧監査を置き換える判断は保留する。** 切り替え前に次の点を直す。

1. G2 は名前のハッシュだけで結合せず、所有元付きの定数を使う。Lean の公理判定を基準にし、外部定数の本体側、帰納型のコンストラクタ、private の値、採取漏れを扱う。
2. 領域ごとの厳格な sorry 条件、型と本体それぞれの禁止依存、所有元・種類・公開性、型を当てる契約を移植する。各条件を新しい検査で落とせるまで旧検査を残す。
3. G3 に文献照合の基準と生成物の検査を加える。生成前に全リンクを解決し、生成後に項目単位でリンクを比較する。主張が変われば同じ名前でも再照合する。
4. 全宣言の母集団を先に確定する。保存成果物を直接読む高速経路を使い、キャッシュに載らない宣言も Lean で埋めてから完了を判定する。
5. G5 は型だけでなく、値の比較方針、公理、属性、引用、旧名の互換条件を契約ごとに明示する。

基準 main は `eedb51893`、レビュー開始時の作業枝は `fc868a3fb`。main の取り込み後、段1から本体・スクリプト・ツールチェーンに差分がないことを確認した。対象は段1の423本と、[ゼロからの設計案](audit-zero-base-design.md)。実験はこの作業枝で bulk 鍵を使い、一時ファイルとログを Git 外に保存した。

## 3. G2 の公理計算と実測

### 採取器と Lean の差

- `dump_all.lean` は現在の import 環境の `env.constants` から所有元を引き、型と値の定数辺を分けて出す。外部定数の名前付き辺は `.xdeps.tsv` の**型だけ**。本体側は件数と、その場で公理と分かる定数しか残らない。外部の定理や定義を経由する公理は別途必要。宣言レコードにも現在は型のハッシュがなく、G3/G5 の前提となる表を別に実装する必要がある。
- Lean v4.35.0-rc4 の `Lean/Util/CollectAxioms.lean` は import 済み定数の保存済み公理を優先する。残りは kernel 環境で判定し、axiom 自身とその型、def/thm/opaque の型と値、ctor/rec の型を読む。inductive では型に加え `ctors` を通り、quot は特別扱いする。型と値の一般的な辺だけではこの規則に一致しない。
- `allowOpaque := true` はアクセスできる値を返す。private と生成補助、公開定理の非公開実装、`.olean/.server/.private` の差を追い、値なし、公理キャッシュあり、採取不能を別状態にする。この試験では通常 import と `importAll` で対象107件の名前と公理は一致した。完全性の判定には、保存成果物ごとの母集団と照合する。
- `Expr.getUsedConstants` の `.proj` は型名と被射影式を訪ねる。射影式の依存を G4 で検査するなら型名とフィールド番号を保存する。生成された射影定数・recursor・instance 宣言はいずれも母集団に入れ、instance の登録先・局所性・優先度を別に扱う。
- `implemented_by` と `unsafe` は実行上の契約。試験の `executable` の Lean 公理集合は空で、実行時の `compiledFast` はその集合に現れない。R5 で実装先、safety、extern 等を別に点検する。
- `Name.hash` は索引に使ってよい。結合時に `Name` と所有元を照合し、実際に import 環境が選んだ所有元を記録する。欠けた節点を空集合で扱わない。グラフ上の到達性には強連結成分の縮約か集合が安定するまでの計算を使う。Lean の公理判定に合わせるときは、再帰時の番兵・キャッシュ順で結果がぶれないかを検証し、保存済みの Lean 判定を優先する。

## 4. R5 の規則と機械で判定できる範囲

README の Conventions は引用の直接適用、文献番号の記録、未証明の仮定束の禁止、依存の向きを定める。`coordination.md` §2.1 は署名に完全な型と依存を書くこと、弱い存在からの choose と指定構成を先に点検することを定める。領域固有の禁止経路は一律の公理表だけで表現できない。`cleanup-log.md` にも、非連結 K の未供給入力7個と S 構成の3個が記録されている。

## 5. R1・R2 とブループリント

`research/*-coverage/` の `items.csv`、`review/ch*.csv`、`statements.csv`、原稿と辺表が入力。`gen_paper.py`、`gen_cited.py`、`gen_lurie.py` は `common.Resolver` を使い、`gen_kerodon.py` は同等の処理を持つ。`gen_clmst.py` には `own` のみリンクする経路がある。`gen_cited.py clmst bs vdescent` の CLMST は他の文献部と同じ状態規則を使う。`gen_blueprint.py` は各部の生成 JSON と一部のレビュー CSV から目次を組む。一部の部の統計は現時点のリンク件数と独立で、任意の生成 JSON がない部は省略される。

| 変更 | 再生成時の現状 | 古い生成物をビルドした場合 |
| --- | --- | --- |
| 改名 | 旧名の候補がなくなると `lean :=` を省いて成功する。リンク数は減り得るが、文献状態と本文は残る。短い名前が別宣言に一意化した場合はそちらを選び得る。 | 旧名が環境になければ止まる。旧別名が有効なら古いリンクが残り得る。 |
| 移動 | 別カードが新しいパスを参照した場合は古いパスの欄からも新所有元を選ぶ。新パスを走査しなければリンクが外れる。行番号は解決の鍵に使わない。 | 旧モジュールが消えていれば import で止まり得る。互換入口から届くなら古い解決のまま。 |
| 削除 | 一つしかなければリンクが消える。複数リンクのうち一つだけ消えるとカードは引き続き linked と数えられ、消えたリンクの表示も残らない場合がある。 | 互換や同名候補がなければ宣言解決で止まる。 |

## 8. 設計の代案と §6 への意見

- 一つの表を用途別に絞る代わりに、共通キーの元に **定数、型辺、値辺、import、属性・位置・可視性、Lean 公理証拠、引用と基準**を保存する。用途ごとに必要な射影を読む。採取の処理はモジュール単位、正当性の判定は所有元とコミット単位に固定する。文字列の型表示は診断に使い、比較は宇宙・束縛子・名前写像のバージョンが明確な構造指紋を使う。
- 公理に関しては Lean が既に書いた確定分を読み、キャッシュ外を小さい Lean 検査で埋める。独立の依存グラフは証拠経路と領域規則に使い、一致確認には負例も入れる。未知の外部定数は要照合とし、許可済みとして通さない。外部側キーには toolchain、パッケージのコミットまたは成果物のダイジェストを含める。
- 許可される未証明入力は、宣言、所有元、型の指紋、引用 ID、許可範囲、直接/推移、主定理から期待するかまで記録する。主定理の3件は現行どおり固定する。root 外も同じルールで報告する。移行時に既存の根を見つけたら、調整役の追認なく許可一覧に混ぜない。
- 対応表の型更新は文献担当の再照合と、調整役による承認の履歴を残す。ユーザーが承認した移動で型が同じなら所在だけ更新できる。数学的な主張・仮定・対応種別の変更には、照合根拠と承認を明記する。
