# 指示書 CD-W1：概念の辞書と概念の木の第一版

作成：2026-11-19（調整役）。決定：ユーザー（11-19）。整理の目標と規則は `declaration-inventory-w1.md` §0（先に読む）。

## 0. 位置づけ

整理の順序は、把握（DI-W1、⑦）→ **概念の辞書 → 概念の木の第一版**（この指示書、⑧）→ その先（木を見てからユーザーと決める）。置き場所の主は概念の木（ユーザー決定）。文献との対応は、文献のブループリントで引く。

**前提（ユーザー、11-19 夕）**：一回で全部うまくいかなくてよい。機械的に全部できなくてよい。辞書の使い道は三つ（木を作る材料、重複を見つける索引、人が読む目次）のどれもで、やりながら形を直す。第一版は粗くてよく、迷った所は印を付けて先へ進む。

**始める時**：⑦ の宣言の表（DI-W1 の 1、`research/declaration-inventory/decls.csv.gz`）が出てから。辞書の候補は表から取る（`structure`・`class`・`inductive` と、値の型の種類が `Sort`・`Prop`・構造体の値の定義）。候補から外すもの、表にないが概念として拾うものは、読んで判断してよい。

この指示書は木の第一版で止まる。深い見直し（定理を読む、重複をまとめる、書き換える）には進まない。

## 1. 前提

- **紙だけ**。Lean の変更・ビルド・鍵の使用なし。ソースと固定版 Mathlib（`.lake/packages/mathlib`）は読むだけ。

## 2. 出力

`research/concept-tree/` と `formalization-plans/stage-ii/consolidation/report-concept-tree.md`（新設）。

1. **概念の辞書**（`concepts.csv`）：一行が一つの概念の宣言。
   - 拾うもの：`structure`・`class`・`inductive` の全部と、**対象を定める定義**（型・構造体・圏・関手の圏・述語（`Prop` を値とする性質）などを定める `def`・`abbrev`）。写像の部品、構成の途中の補助、定理は拾わない。拾うか迷うものは拾って印を付ける。
   - 列：名前、ファイル:行、種類、型（引数と値の型）、docstring の要約（なければ中身から一行）、数学の内容の一行（日本語、分野の専門家に通じる言葉で）、使う概念（辞書の中の他の行）、文献の番号（docstring・属性・対応表にあれば）、**Mathlib の同じ概念**（あれば宣言名とファイル。関係は「同じ・本体が特殊・本体が一般・似ているが別」）、**本体の中の似た概念**（同じ対象の別の定義・模型。行の名前を並べる）、確信度。
   - **二層にする**：主要な概念（専門家が目次として読むもの。数百個の見込み）と、補助の定義（主要な概念にぶら下げる）。主要な概念には説明を丁寧に、補助の定義には似た定義と Mathlib の対応を。どちらかは、使われる数・構造体かどうか・文献に名指しされているか、を手がかりに読んで決める。
   - 拾わなかった `def` の数を、ディレクトリごとに数えておく（辞書の網羅を後で確かめるため）。
2. **概念の木の第一版**（`tree.md` と `tree.csv`）：辞書の全ての行を、数学の主題の木に配る。
   - 木の上の段は Mathlib のディレクトリの構造を参考にする（例：`Algebra`・`RingTheory`・`CategoryTheory`・`AlgebraicTopology`・`AlgebraicGeometry`・`Topology` など）。Mathlib にない主題（∞ 圏、スペクトル、K 理論、prism、perfectoid など）は、Mathlib に入れるならどこか、を考えて置く。
   - 文献ごとの枝は作らない（Kerodon・HTT・HA・BS・KST の節で分けない）。模型が複数ある概念は、一つの概念の下に模型を並べる。
   - 節ごとに：題、数学の内容の一文、属する概念の行、今それらがあるディレクトリ（複数に散っていれば全部）。
   - `tree.csv` は、概念の行 → 木の節の対応（一つの概念は一つの節）。
3. **所見**（報告に）：
   - 同じ概念が複数の場所・複数の定義である箇所の一覧（辞書の「本体の中の似た概念」から）。
   - Mathlib に同じ概念がある行の一覧と数。
   - 木の節ごとの大きさ（概念の数と、その概念を主張に含む定理の数・行数。⑦ の表と依存の辺から数える。定義は少ないが補題が多い主題を見落とさないため）。
   - 置き場所に迷った概念と、その理由。
   - 木の切り方で判断が分かれる所（二通りの案を並べる。決めない）。

## 3. 進め方と止まるところ

- 量が多いので、今のディレクトリごとに辞書を作ってコミットし（`InfinityCategories` は下位のディレクトリごと）、全部そろってから木を作る。木は全体を見て一度に作る（ディレクトリごとに作らない）。
- 途中で一度、辞書が二つか三つのディレクトリ分できた所で、形（列・粒度・拾い方）を短く報告して続ける（止まらない）。
- **木の第一版と所見の報告で止まる**。報告に「一覧：済み n／全体 m」（単位は辞書のディレクトリと、木・所見）。
- 守ること：重複をまとめる案、書き換えの案、ファイルやディレクトリの移動の案は書かない（所見に事実を並べるだけ）。数学の内容は、ソースと原典から確かめたことだけを書き、推測には印を付ける。
