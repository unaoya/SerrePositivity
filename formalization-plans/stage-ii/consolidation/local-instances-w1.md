# LI-W1　構造の登録を一か所にする（局所 instance の置き直しをやめる）

規則は [cleanup-rules.md](cleanup-rules.md)。一回の依頼は一段。記録は `report-local-instances.md`。

## 0. 背景（11-21）

本体には、すでにある構造（豊穣化、モデル構造、Kan 性、加群の構造など）を、使うファイルごとに局所 instance として宣言し直す書き方が広がっている。調整役がソースを数えた結果（`research/cleanup-zero-base/local-instances/`、main ca7e5e807）：

- `local instance …` が 3,210 件（1,706 ファイル）。型で分けると 714 種。一度だけのものが 369 種。何度も宣言されて中身が毎回同じものが 288 種・2,078 件。中身の書き方が複数あるものが 57 種・763 件（多くは同じものの別の書き方）。
- `attribute [local instance] …` が 1,604 件（166 種の宣言）。うち `HasDerivedCategory.standard` が 675 件。
- 多いもの：Ω スペクトルの単体的豊穣化 475、その写像空間の Kan 性 109、基点付き単体集合の単体的豊穣化 102、Barratt–Eccles の代数のモデル構造 77 と分解 65、Rees 代数の商の次数付き環 56、Reedy モデル構造 45 など。

数学の内容は増えていないのに宣言が増え、どの構造を使っているかが読み手に見えにくい。

## 1. 規則（ユーザー承認、11-21）

1. **一つの型に、その種類の構造が一つしか無いものは、定義した所で全体の instance として登録する。** 使う側は何も書かない。
2. **同じ型に複数の構造がありうるもの**（モデル構造など）と、**仮定つきで推論に載せにくいもの**（「p が左ファイブレーションならファイバーは Kan」の類）は、名前空間を開いたときだけ有効にする（scoped instance）。使う側は `open scoped …` の一行で、どれを使っているかが明示される。
3. **Mathlib の作法があるものはそれに従う。** 導来圏：Mathlib は、導来圏を含む主張では変数 `[HasDerivedCategory.{w} C]` を置き、`HasDerivedCategory.standard` は「導来圏を含まない主張を示す証明の冒頭」でだけ使う、としている（`Mathlib/Algebra/Homology/DerivedCategory/Basic.lean` の Implementation notes。局所化した圏の射は宇宙 `max u v` に入るが、もっと小さい宇宙に収まる選び方がありうるので、選び方を固定しない）。

## 2. 段 1：分類と試し（コミットするのは表と報告だけ）

1. 714 種（`local-instances.csv`）と 166 種（`local-instances-attribute.csv`）を、規則 1・2・3 と「一度だけなのでそのまま」「判断できない」に分ける。分けるときは、元の定義を読み、同じ型に別の構造が本体か Mathlib にあるかを、宣言の表（記録監査の `instances` の欄を含む）で調べる。名前で決めない。
2. 中身の書き方が複数ある 57 種は、本当に別のものか、同じものの別の書き方かを確かめる。別のものがあれば、それが二重の構成（同じ型に同じ種類の構造を二通り作っている）かどうかを報告する。
3. 件数の多い上位 50 種について、規則どおりに登録を直した場合に建つか・遅くならないかを、作業木で試す（その構造を定義するファイルと、使う側から選んだ十数ファイル）。試した差分はコミットしない。型クラスの推論が別の経路を拾って主張が変わる例、遅くなる例、instance の循環が出る例を記録する。
4. **導来圏の 675 件**：`HasDerivedCategory.standard` を局所で有効にしている所のうち、**主張に導来圏が現れる宣言**（Mathlib の作法では変数にすべきもの）と、証明の中だけで使っている所を分けて数える。主張に現れるものについて、変数 `[HasDerivedCategory.{w} C]` に直した場合に何が変わるかを報告する（直さない）。
5. 置き直しではなく、**その場で構造を作っている**もの（`where` で中身を書いている 12 件と、右辺が長い式のもの）を一覧にする。これは一般論の適用にすべき候補（EN-W1 と同じ方針）。

## 3. 段 2 以降

ユーザーの承認の後、種類ごとに登録を一か所にして置き直しを消す。全体の再ビルドになるので、ほかのレーンと重ならない時にまとめて取り込む。
