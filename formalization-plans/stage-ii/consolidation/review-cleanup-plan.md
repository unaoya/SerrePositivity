- カーネル定数、ソースのコマンド、環境拡張への登録を別々に数える必要がある。`SerrePositivity/Util/DeprecatedAlias.lean:27,34` は拡張とコマンド elaborator、`SerrePositivity/Util/Citation.lean:56–83` は引用・構文・属性の登録。`Spectra/ModelCategory/SimplicialGenerators.lean:11–22`（以下、本体の相対パスは `SerrePositivity/` 下）は alias の列、Kerodon の `LeftAndRightFibrations/JoinCells.lean:50,59` は一つの deriving から複数の instance を要求する。匿名でも人が書いた instance と deriving の生成物は別。mutual では一コマンドに複数の本宣言と共有の補助があり得る（既存分割器の拒否テスト `scripts/refactor/test_refactor_tools.py:58–59`）。名前の最長接頭辞（snapshot 35–38行）は namespace 内の手書き定理にも成立する。親は多対多・不明を許し、構造体情報、constructor/recursor の所属、コマンド位置で裏を取る。`Spectra/General/Basic.lean:65` の手書き mk は接尾辞で生成扱いにできない。
- 二重確認が双方とも見落とすのは、キーワードを含まない生成コマンドの出力を「生成なので照合外」にした場合、範囲なしを双方から落とした場合、同じ行の二宣言の片方欠落と他方の二重帰属が相殺する場合。数が等しくても内容は違う。ソース SHA と olean の対応を記録し、コマンドの開始・終了位置（列込み）ごとの生成 ID 集合、位置なし ID、定数を作らないコマンドを別勘定にする。alias、derived instance、private、mutual、空の集約を少数の既知例で照合。取得不能と理由づけ済みの範囲不明を件数別に報告し、「理由不明 0」だけで完了判定しない。
