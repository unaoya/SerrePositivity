## 内部ビルドの失敗

共有鍵の下で、統合先 78＋移動先 33 の 111 モジュールを指定した `lake build` を実行した。正確な argv は `.lake/verify/dg-w2-b/internal-state.json` に保存。

```sh
zsh scripts/refactor/with_build_lock.sh -- python3 -B /tmp/dgw2b/internal.py
```

停止までの監督プロセスの所要時間は **275.057 秒**。新規成功 **108 モジュール**、失敗 **1 モジュール・14 エラー**を観測した。許可範囲で直せない衝突と確認した時点で中断し、終了コードは **143**。全対象を走り切った結果ではない。

対象は `SerrePositivity.DifferentialGraded.Functor.ModuleShiftOpposite`。最初のエラーは次のとおり。

```text
error: SerrePositivity/DifferentialGraded/Functor/ModuleShiftOpposite.lean:19:19: Application type mismatch: The argument
  op (shiftModule s M)
has type
  DGFunctor A Dᵒᵖᵒᵖ (Complex A)ᵒᵖ
but is expected to have type
  (RightModule A D)ᵒᵖ
in the application
  F.obj (op (shiftModule s M))
```

エラー位置は 19:19、19:50、20:9、23:19、23:34、25:11、30:10、28:62、39:53、41:4、60:53、62:4、78:10、78:42。28:62 の unsolved goals は前の名前解決エラーに続くもの。

このファイルのコード変更は import の `Bimodule.UncurryHom → Bimodule.Tensor` だけ。以前は `Functor.Opposite` に到達せず、統合後に次の経路ができた。

```text
Functor.ModuleShiftOpposite
  → Bimodule.Tensor
  → Bimodule.Value
  → Functor.Opposite
```

`Functor/Opposite.lean:16` は `namespace SerrePositivity.DifferentialGraded.DGFunctor` の中に `def op` を宣言する。失敗したファイルも同じ namespace であり、従来の無修飾 `op` が `Opposite.op` から `DGFunctor.op` に解決される。統合先 `Bimodule.Tensor` にはこのファイルが使う `complex_unitElement`（163 行）もあるため、この import を単に除くこともできない。

許可された直接 import の追加では、既に現在の namespace に届いている同名宣言を隠せない。`Opposite.op` への完全修飾、または別途検討する名前解決の制御が必要である。今回はその編集を行っていない。

今回の衝突は「使用していた宣言への到達性が失われる」ケースではなく、「統合で新たに届く同名宣言が無修飾名を隠す」ケースである。uses_modules の到達性検査が 0 件でも検出できなかった点として記録する。
