# 概念の割り当ての独立な確認（答えを見ない分類、二回目）

Lean 4 + Mathlib の形式化プロジェクト（SerrePositivity、約 16 万宣言）で、全宣言を数学の概念に分けた（94 の概念）。その割り当てが正しいかを確かめるために、無作為に選んだ宣言を、**今の割り当てを見ずに**分類してほしい。あなたには今の割り当ては渡していない。後でこちらで照合する。

## 入力（このディレクトリ）
- `<batch>.csv`：宣言 160 個。列は id、declaration（完全名）、kind、file、line、source_text（ソースの先頭 800 字。docstring があれば含む）。
- `concepts.txt`：概念の一覧（完全名「大分類/概念」）。右の「土台」は、その概念が上に作られている概念（その概念の定義が使っている概念）と、その割合。
- `definitions.md`：概念の定義書。概念ごとに「入るもの」「入らないもの（隣の概念との境目）」「小概念」。**判断の基準はこれ。** 末尾の「調整役の補足」は本文より優先する。

## 分類の規則
1. **主張（型）に現れる概念で決める。** 定理なら主張に現れる対象・構成・性質、定義なら型と（型だけで分からなければ）本体。証明の中で使っている道具は見ない。
2. **宣言が置かれているファイル・名前空間・宣言の名前の文字列で決めない。** 特定の理論のために書かれた一般的な補題（オペラドのための置換の等式、S 構成のための単体集合の補題）は、主張に現れるのが一般の概念だけなら、一般の概念（組合せと順序、単体集合（基本）など）に入れる。
3. **主張に複数の概念が現れるとき**：一方がもう一方の土台（`concepts.txt` の「土台」、または定義書から明らか）なら、土台の側を除き、上に作られている側を選ぶ。例：dg 加群の導来圏についての補題には複体・dg 圏・dg 加群も現れるが、「導来圏と Perf（dg 加群）」。
4. **互いに土台でない概念が二つ以上残るとき**（二つの概念を結ぶ宣言。比較定理、両立の補題など）：`concept` に一つ、`alt` にもう一つを書き、`relation` を true にする。どちらを concept にするかは問わない。
5. 証明の足場かどうか、止めた経路の部品かどうかは、概念の選択に使わない。
6. `source_text` で判断できないときは、file の line を開いて読む。主張に出てくる定義が何か分からないときは、その定義を検索して読む（リポジトリの root は /Users/sugakubunka/Documents/LEAN_Projects.nosync/SerrePositivity、読むだけ。ビルドや Lean の実行はしない。何も書き換えない）。

## 出力
`out/<batch>.json`（UTF-8）：

    {"r0-000": {"concept": "<concepts.txt の完全名 または NONE>", "alt": "<完全名 または 空>", "relation": false, "confidence": "high|mid|low", "note": "一言（主張に現れる概念と、選んだ理由）"}, …}

- `alt`：relation が true のときはもう一方の概念。false のときは、迷った二番目の候補（なければ空）。
- `confidence`：high（主張を読んで明らか）、mid（二つで迷った）、low（定義の中身を追いきれなかった）。
- どの概念にも合わなければ concept を `NONE` とし、note に何の概念かを書く。
- 全ての id を入れる（160 件）。concept と alt は concepts.txt の完全名と一字一句同じにする。書いた後、JSON として読めること、件数、名前が concepts.txt にあることを確かめる。

最後の返答は短く：confidence の内訳、relation の件数、NONE の件数、定義書で境目が決まらなかった組（具体的に、id を添えて）。
