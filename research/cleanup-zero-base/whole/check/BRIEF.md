# 概念の割り当ての独立な確認（答えを見ない二度目の分類）

Lean 4 + Mathlib の形式化プロジェクト（SerrePositivity、約 16 万宣言）で、全宣言を数学の概念に分けた（94 の概念、`concepts.txt`）。その割り当てが正しいかを確かめるために、無作為に選んだ宣言を、**今の割り当てを見ずに**もう一度分類してほしい。あなたには今の割り当ては渡していない。後でこちらで照合する。

## 入力（このディレクトリ）
- `<batch>.csv`：宣言 160 個。列は id、declaration（完全名）、kind（thm / def / inductive など）、file、line、source_text（ソースの先頭 700 字。docstring があれば含む）。
- `concepts.txt`：概念の一覧。行頭が概念の完全名（「大分類/概念」）、字下げした行はその概念の主な小概念（参考）。

## やること
各宣言について、**その宣言が何についての主張・定義か**を読み、`concepts.txt` から最も合う概念を一つ選ぶ。

- 判断は宣言の**主張（型）**による。定理なら「何についての定理か」、定義なら「何を定義しているか」。証明の中で使っている道具ではなく、主張の主語。
- 主張に複数の概念が現れるときは、**最も特殊な（下流の）概念**を選ぶ。例：dg 加群の導来圏についての補題は「複体」ではなく「導来圏と Perf（dg 加群）」。K スペクトルの関手性の補題は「Ω スペクトル」ではなく「S 構成と K スペクトル」。
- `source_text` で判断できないときは、file の line を開いて読む（リポジトリの root は /Users/sugakubunka/Documents/LEAN_Projects.nosync/SerrePositivity、読むだけ。ビルドや Lean の実行はしない。何も書き換えない）。主張に出てくる定義が何か分からないときは、その定義を検索して読む。
- **名前空間・ファイルの場所・宣言の名前の文字列で決めない。** 名前に join とあっても結とは限らない、名前空間が K 理論でも中身が単体集合の一般論なら単体集合、という誤りが実際に多かった。
- 二番目に合う概念があれば `alt` に書く（なければ空）。どの概念にも合わないと思えば concept を `NONE` とし、note に何の概念かを書く。
- 確信の度合いを confidence に：`high`（主張を読んで明らか）、`mid`（二つで迷った）、`low`（定義の中身を追いきれなかった）。

## 出力
`out/<batch>.json`（UTF-8）：

    {"b0-000": {"concept": "<concepts.txt の完全名 または NONE>", "alt": "<完全名 または 空>", "confidence": "high|mid|low", "note": "一言（何についての宣言か）"}, …}

全ての id を入れる（160 件）。concept と alt の文字列は concepts.txt の完全名と一字一句同じにする。書いた後、JSON として読めること、件数、名前が concepts.txt にあることを確かめる。

最後の返答は短く：confidence の内訳、NONE の件数、概念の一覧について気づいたこと（境目が曖昧で選びにくかった組など）。
