# 概念の木の二段目を作る（読む作業）

Lean 4 + Mathlib の形式化プロジェクト（SerrePositivity、約 16 万宣言）で、「どういう数学の概念が形式化されているか」を、今のファイルやディレクトリの構成を無視してゼロから整理している。一段目（幹）は 91 の概念に分けてある（trunk-concepts.txt、右は宣言の数）。あなたの仕事は、指定された大きい概念を、中の定義を読んで二段目（小概念）に分けること。

## 入力（このディレクトリ）
- `<key>.csv`：その概念に属する定義（核）の一覧。列は definition（完全名）、declarations_assigned（その定義を主張に含む宣言の数）、type_users、docstring（先頭）、signature（先頭）、file、line。
- `<key>.mathlib.txt`：その概念の宣言のうち、主張に本体の定義が現れないもの（Mathlib の定義だけについての補題）について、主張に現れる Mathlib の定数と回数。
- `trunk-concepts.txt`：幹の全概念。

## やること
1. `<key>.csv` の全行を読む。docstring と signature で内容が分からない定義は、file の line を開いて確かめる（リポジトリの root は /Users/sugakubunka/Documents/LEAN_Projects.nosync/SerrePositivity、読むだけ。ビルドや Lean の実行はしない。リポジトリの中は何も書き換えない）。
2. 数学の内容で小概念に分ける。一つの概念につき 4〜12 個。小概念の名前は日本語の数学用語（例：「左ファイブレーション」「cocartesian ファイブレーション」「ファイバーと輸送」「straightening」）。**ファイルの場所・名前空間・ディレクトリの名前で分けない。** 定義が何であるか（何についての定義か）で分ける。文献の節が分かるものは添える（Kerodon・HTT・HA・原論文など、定義の docstring に書いてあることが多い）。
3. 全ての定義を、ちょうど一つの小概念に入れる。この概念に属さないと判断した定義は、小概念の代わりに `MOVE:<幹の概念の完全名>` を入れる（trunk-concepts.txt の名前。該当がなければ `MOVE:?` とし、notes に理由）。
4. 証明の道具・添字の型・補助の構成（数学の概念というより、ある証明のための足場）は、小概念「（補助）<何の補助か>」に入れてよい。無理に概念の名前を付けない。
5. `<key>.mathlib.txt` に 100 件以上の宣言がある場合は、Mathlib の定数の名前から小概念への規則も作る（正規表現と小概念の組の列。上から順に当て、最初に当たったものに入れる。特殊なものを上に、最後は受け皿）。

## 出力
概念ごとに `out/<key>.json`（UTF-8、このディレクトリの out/ の下）を書く：

    {"key": "c00", "concept": "<幹の概念の完全名>",
     "subconcepts": [{"name": "…", "description": "一行の説明", "reference": "文献と節（分かれば、なければ空）"}],
     "assign": {"<definition の完全名>": "<小概念の name または MOVE:…>"},
     "mathlib_rules": [["<正規表現>", "<小概念の name>"]],
     "notes": "分け方で迷った所、幹の概念の名前や範囲について気づいたこと（短く）"}

`assign` には csv の全ての定義を入れる（件数が一致すること）。書いた後、JSON として読めることと件数を確かめる。

最後の返答は短く：概念ごとに小概念の名前と件数、MOVE の件数、気づいた点を数行。
